# 읽기 화면: 북마크·목차·숨김 규칙 / Reader navigation design

날짜: 2026-10-30. 사용자 요청: 긴 세션(30만 줄 기록)을 처음부터 소설처럼 읽어 내려가고 싶다.

## 문제 (사용자 말)

1. 처음부터 읽는 방법이 없다.
2. 챕터로 나뉘지 않아 여기가 어디인지 모르고, 원하는 곳으로 빨리 갈 수 없다. 여러 게임에서 동작해야 하고, 아예 나뉘지 않으면 불편하다.
3. 반복해서 읽고 싶지 않은 문장이 있다. 시스템 문구 중에도 보고 싶은 것과 아닌 것이 있다.
4. (추가) 읽던 곳을 북마크하고 바로 가고 싶다.

PC와 휴대폰 보기 둘 다 지원한다. UI는 shadcn 컴포넌트만.

## 저장: 게임 폴더의 `rpg-viewer/reader.json`

북마크, 숨김 규칙, (선택) 챕터 변수를 담는다. PC·따로 띄운 창·휴대폰 보기가 같은 파일을 쓴다.
`favoritesFile.ts`/`FavoritesProvider.tsx`와 같은 방식: 쓸 때마다 디스크 파일을 먼저 읽고 이 뷰어에서 바꾼 것만 얹어 쓴다(merge),
읽기 실패(파일 없음과 구분)면 덮어쓰지 않는다. 모든 core 함수는 예외를 던지지 않는다.

```
{ v: 1,
  bookmarks: [{ id, branch, seq, name, t }],              // seq = 그 줄의 기록 seq, branch = 대표 갈래
  hide: [{ id, kind: "exact"|"digits"|"type", ... , t }],  // 아래 숨김 규칙
  chapterVar?: number | null,                               // 고른 날짜·진행 변수 id
  t }
```

읽던 위치(readSeq)는 지금처럼 기존 저장(readPosition)을 쓴다.

## 1. 바로 가기·북마크

- 읽기 본문 위(휴대폰은 `보기 설정` 옆 버튼)에 `목차` 버튼. 목차 맨 위 고정 항목: `처음`, `읽던 곳`, `맨 끝`, 그 아래 북마크 목록(이름·위치 설명·지우기·이름 바꾸기).
- 각 읽기 줄의 메뉴(아래 3과 같은 메뉴)에 `여기 북마크`. 기본 이름은 줄 글 앞 20자 정도.
- 이동은 기존 구간 창(readerWindow: 300항목 구간 + extendUp/Down)을 목표 항목 근처로 다시 잡고 그 항목으로 스크롤한다.
  `처음` = 첫 항목. 이동하면 `자동으로 맨 아래로`는 꺼진다(맨 끝 이동은 예외).
- 북마크 seq가 지금 갈래 경로에 없으면(다른 갈래) 그 갈래로 바꾼 뒤 이동한다. 기록에서 사라진 seq면 `찾을 수 없음`으로 흐리게.

## 2. 목차 (자동 두 단계 + 선택 변수)

순수 함수 `src/core/live/chapters.ts`가 읽기 항목(지금 갈래 경로의 ReaderItem 목록 + 각 항목의 기록 시각)으로 목차를 만든다.
기록이 덧붙을 때 새 부분만 이어 계산한다(lineage, `readerPath.ts` 방식).

- **큰 단위 = 플레이 묶음**: 이웃한 기록의 시각(t) 차이가 20분을 넘으면 새 묶음. 제목은 시작 날짜·시각과 길이(예: `10월 28일 밤 · 2시간 10분`).
  어떤 게임이든 시간 정보는 있으므로 항상 나뉜다. 묶음이 하나뿐이어도 장면 목록은 나온다.
- **작은 단위 = 장면**: 같은 출처(src: 맵 이벤트/커먼 이벤트)에서 온 대사가 이어진 덩어리(장소 이동·갈래 시작에서 끊김). 대사 10줄 이상이면 목차에 올린다.
  제목: `맵 이름 · 이벤트 이름`(커먼 이벤트면 그 이름), 부제: 첫 대사 한 줄(40자 정도). 같은 출처의 장면을 이미 봤으면 `다시 본 장면` 표시(흐리게).
  긴 목록이라 묶음별 접기(Collapsible)와 읽음 표시(읽던 곳보다 앞이면 읽음).
- **선택: 날짜·진행 변수**: 목차 아래 `날짜 변수로 나누기`. 후보 = 기록에서 거의 오르기만 하고(내려간 횟수 ≤ 2) 바뀐 횟수가 적은(3–300) 변수,
  이름에 `일|日|day|date|진행|章|chapter|週|week|月|month` 같은 글자가 있으면 위로. 후보는 이름·바뀐 횟수·값 흐름(1→2→…→14)으로 보여준다.
  고르면 큰 단위가 그 변수 값이 바뀌는 곳마다 `「이름」 값`이 된다(플레이 묶음 대신). `자동(플레이 시간)`으로 되돌릴 수 있다.
- 읽기 본문에는 큰 단위 경계에 챕터 제목 줄(기존 `chapter` 항목 모양)이 들어가고, 화면 위에 지금 위치 한 줄(예: `10월 28일 밤 · 37%`).
- PC: 목차는 Sheet(오른쪽). 휴대폰: Drawer.

## 3. 숨김 규칙 (보고 싶은 것만 남기기)

모든 읽기 줄(대사·스크롤 글·알림·전투 로그·플러그인 명령)에 작은 메뉴(DropdownMenu, 휴대폰은 길게 누르기 또는 같은 메뉴 버튼):

- `이 문장 숨기기` — 같은 글(공백 정리 후 완전히 같음)만. `{ kind: "exact", text }`
- `숫자만 다른 문장도 숨기기` — 숫자 덩어리를 같게 본다(예: `골드 120 획득` ↔ `골드 35 획득`). `{ kind: "digits", pattern }`
- `이 종류 모두 숨기기` — 종류 단위. `{ kind: "type", type }`: 알림은 알림 출처·종류(기존 noticeKind/source), 플러그인 명령은 명령 이름,
  전투 로그 전체, 전투 기록 전체 등. 대사(message)에는 이 항목이 없다(이야기 글이 통째로 사라지는 것을 막음).
- 숨긴 줄이 이어진 자리에는 `숨긴 문구 N줄` 한 줄만 남고 누르면 잠깐 펼쳐 볼 수 있다.
- `숨긴 문구` 관리(목차/보기 설정 안): 규칙 목록, 각 규칙이 숨기는 줄 수, 되돌리기.
- 기존 스위치 `플러그인 명령 모두 보기`·`전투 기록 보기`·`알림 문구 보기`(+ NoticeKindsMenu, 플러그인 명령별 항상 보이기/숨기기)는
  이 규칙으로 옮긴다: 예전 설정값은 처음 한 번 규칙으로 바꿔 넣고(migration) 스위치는 없앤다. 기본값은 지금과 같게(지금 숨겨지는 것은 계속 숨김).
  기록·체크리스트 등 다른 화면이 쓰는 pluginDisplay 동작은 깨지지 않게 한다.
- 숨김은 읽기 화면의 보기만 바꾸고 기록은 건드리지 않는다. 목차의 장면 줄 수는 숨김과 상관없이 센다.

## 성능

30만 줄 기록에서 앞선 성능 작업(읽기 이어 계산, 숨은 읽기 멈춤)을 깨지 않는다. 목차·숨김 판정은 새 항목만 이어 계산하고,
숨김 규칙이 바뀔 때만 전체를 다시 본다. 목차는 열 때만 그린다(수백 줄이면 묶음별 접기로 충분).

## 테스트

- core: `chapters.ts`(묶음 경계, 장면 덩어리·10줄 문턱·다시 본 장면, 변수 후보·경계, 이어 계산 = 전체 계산), 숨김 규칙 매칭(exact/digits/type),
  `reader.json` 읽기·merge·실패 시 덮어쓰지 않음, 예전 설정 migration. 합성 기록만 쓴다.
- 확인: `npx vitest run`, `npx tsc -b --noEmit`, `npm run lint`, `npm run build`.

## 구현 순서

1. reader.json 저장 + 북마크 + 바로 가기(처음/읽던 곳/맨 끝) + 목차 틀(Sheet/Drawer).
2. 자동 목차(플레이 묶음 + 장면) + 본문 챕터 줄 + 지금 위치 줄, 그다음 선택 변수.
3. 숨김 규칙 + 줄 메뉴 + `숨긴 문구 N줄` + 관리 목록 + 예전 스위치 migration.

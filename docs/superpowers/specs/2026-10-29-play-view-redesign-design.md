# 플레이 화면 다시 짜기 (PC·휴대폰) — 설계

## 왜

사용자가 실제로 쓰는 방식과 지금 화면이 반대다.

- PC: 모니터를 반으로 나눠 오른쪽 반은 게임, 왼쪽 반(가로 약 900~960px, 세로 전체)은 뷰어.
- 휴대폰: 아이패드로 PC 게임을 원격 플레이(게임패드에 단축키)하고, 휴대폰으로 뷰어를 본다. 아이패드에서는 뷰어를 쓰지 않는다.
- 자주 보는 것: 맵(맵 **그림**이 핵심), 게임 보조(뷰어에서 직접 누름 — 단축키를 아직 못 외움), 치트(변수 수정, 아이템 찾기·수정. 스위치는 안 씀).
- 읽기는 놓쳤을 때만 본다.

지금은 읽기가 화면 중심이고, 맵은 오른쪽 칸 안에서 다음 스토리(최대 40%)와 해 볼 것 목록(최대 45%)에 밀려 창을 늘려도 짜부된다. 치트·보조는 덮이는 창이라 맵을 가린다.

## 성공 기준

- 맵 그림이 어떤 창 크기에서도 크게 보인다(다른 것에 비율로 밀리지 않는다).
- 자주 쓰는 보조 조작은 클릭 한 번(맨 위 줄).
- 치트·보조를 쓰는 동안 맵이 가려지지 않는다.
- 기능 하나만 따로 창으로 띄울 수 있고, 창 위치·크기를 기억한다.
- 즐겨찾기(보조·치트)는 게임 폴더별로 저장되어 PC·따로 띄운 창·휴대폰에서 같다.

## 1. PC 화면

**맨 위 줄(항상)**: 연결 상태·지금 맵 이름, 그리고 **보조 즐겨찾기**만.

- 보조 탭의 각 기능 옆 ☆로 맨 위 줄에 올리고 내린다.
- 기본 즐겨찾기: 배속(×1/×2/×4/×8), 본 대사 넘기기, 본 이벤트 자동 배속(켜기·빠르기), 전투 이기기·지기·도망, 적 체력 100%·1%, 내 체력 100%·1%.
- 전투 기능은 즐겨찾기여도 전투 중에만 보인다. 확인 절차(지기 확인, 도망 불가 등)는 보조 탭과 같다.
- 실행·휴대폰으로 보기·백업·게임 설정은 `⋯` DropdownMenu로.

**본문**: 좌우 Resizable 두 칸(크기 기억).

- 왼쪽 **맵 칸**: 맵 그림이 칸을 채운다. 아래에 `해 볼 것 N | 다음 스토리` 탭 칸(세로 Resizable, 접을 수 있음, 크기 기억). 해 볼 것 줄을 누르면 맵이 그 점으로, 맵 점을 누르면 목록이 그 줄로(지금 동작 유지).
- 오른쪽 **도구 칸**: Tabs `치트 | 보조 | 읽기`(마지막 탭 기억). 치트·보조는 칸 안에 그대로 그린다(덮이는 Sheet/Popover 아님).
- 좁은 창(PLAY_BREAKPOINT 900px 미만): 위 맵 칸, 아래 도구 칸으로 쌓는다. 맵 칸은 최소 높이를 가진다.

## 2. 따로 창으로 떼기

- 맵 칸과 도구 칸의 각 탭(치트·보조·읽기)에 "새 창으로 떼기" 버튼. 그 모듈만 있는 창을 연다(같은 앱, URL에 모듈 이름).
- 모듈별로 창 위치·크기(screenX/Y, outerWidth/Height)를 저장하고 다음에 같은 자리로 연다(window.open features). 브라우저가 막으면 가까운 자리.
- 떼어 낸 모듈은 원래 창에서 "따로 창에서 보는 중 · 다시 가져오기"로 표시. 따로 창이 닫히면 원래 자리로 돌아온다(BroadcastChannel 또는 storage 이벤트로 알림).
- 기존 "새 창으로 열기"(PlayView popup)는 이 방식으로 바뀐다.
- 창 위치·크기와 떼어 낸 상태는 이 PC 브라우저의 localStorage(기기별이 맞다).

## 3. 휴대폰

- 아래 탭: `보조 | 치트 | 맵 | 읽기`, 처음 열면 보조. 마지막 탭 기억은 유지.
- 보조 탭: 맨 위에 보조 즐겨찾기를 큰 버튼으로(전투 중이면 전투 버튼이 맨 위). 그 아래 나머지 보조(세이브·백업·단축키 설정 등).
- 치트 탭: 변수 즐겨찾기가 먼저, 아이템 찾기는 바로 옆. 스위치는 뒤로.
- 맵 탭: 맵 그림이 화면을 채우고, 해 볼 것·다음 스토리는 아래에서 끌어 올리는 Drawer.
- 위쪽의 게임 도구 버튼과 그 Sheet는 없앤다(보조·치트가 탭이 되므로). 새 선택지가 뜨면 읽기로 넘기는 동작은 유지.

## 4. 즐겨찾기 저장(게임 폴더별)

- 게임 폴더의 `rpg-viewer/favorites.json`에 저장: 보조 즐겨찾기(기능 목록과 순서), 치트 즐겨찾기(스위치·변수 id, 붙인 이름).
- control.json과 같은 방식: 쓸 때마다 디스크 파일을 먼저 읽고 바꾼 부분만 얹어 쓴다. 다른 뷰어(휴대폰·따로 창)의 변경은 주기적으로 읽어 반영한다. 휴대폰 보기는 이미 /api/fs/read·write로 게임 폴더를 읽고 쓴다.
- 쓰기 권한이 아직 없으면(PC 브라우저 폴더 권한) localStorage에 두었다가 권한이 생기면 파일로 옮긴다. 파일이 없으면 지금 localStorage의 치트 즐겨찾기(`rpgv.cheatFavorites.<gameKey>`)를 가져와 첫 파일을 만든다.
- 깨진 파일은 무시하고 기본값으로(예외를 던지지 않는다).

## 그대로 두는 것

읽기 화면 내부(보기 설정·갈래·선택 흐름), 치트·보조 기능 자체, 단축키, 플러그인. 배치와 진입 경로만 바뀐다.

## 구현 단위

1. **즐겨찾기 저장소**: core 순수 로직(파싱·병합·기본값) + favorites.json 읽기/쓰기 훅. 치트 즐겨찾기 이전.
2. **모듈 분리**: CheatSheet·AssistPanel 내용을 덮개 없이 쓸 수 있는 컴포넌트로(CheatContent·AssistContent), PlayMap을 맵 그림 / 해 볼 것 / 다음 스토리로 나눠 쓸 수 있게.
3. **PC 화면**: 맨 위 즐겨찾기 줄, 맵 칸, 도구 칸, 쌓기 배치.
4. **따로 창**: 모듈 창 라우트, 창 위치 기억, 떼기·되돌리기 알림.
5. **휴대폰 화면**: 탭 순서·보조 탭·치트 탭·맵 탭 Drawer.

1·2 다음에 3·4·5. UI는 shadcn 컴포넌트만.

## 확인

- 단위: 즐겨찾기 파싱·병합·이전, 창 위치 저장·복원 계산, 기본 즐겨찾기.
- 화면: 개발 서버에서 PC 960x1040, 좁은 창 600x1000, 휴대폰 390x844 스크린샷으로 맵 크기와 탭 동작 확인.

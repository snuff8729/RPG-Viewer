# 화면 설계 가이드

RPG Viewer의 화면을 고치거나 기능을 더할 때 따르는 규칙입니다. 2026-11 출시 전 전체 리디자인(설계: [docs/superpowers/specs/2026-11-01-release-ux-redesign-design.md](superpowers/specs/2026-11-01-release-ux-redesign-design.md))과 그 뒤 사용자 피드백에서 정한 것을 모았습니다. 규칙마다 **왜**를 붙였습니다. 이유가 사라지지 않았다면 규칙도 지켜 주세요.

## 1. 누구를, 어떤 순간을 위해 만드나

- 사용자는 **게임을 하면서 옆에 뷰어를 띄워 둡니다.** PC는 모니터 왼쪽 반(가로 약 900~960px, 세로 전체), 또는 휴대폰.
- 가장 자주 하는 일: 맵에서 무엇과 상호작용할 수 있는지·해야 할 것 확인, 게임 보조(배속·본 대사 넘기기·전투 건너뛰기), 전투 처리.
- 그다음: 게임을 끄고 내 플레이를 다시 읽기, 게임 없이 이벤트·대사 찾아보기.
- 드물게: 플러그인 설치·게임 위치·백업·휴대폰 연결·게임 맞춤 설정·진단.
- **휴대폰은 PC와 같은 비중**입니다. 휴대폰을 "축소판"으로 만들지 않습니다.

새 기능을 넣을 자리는 이 빈도 순서로 정합니다. 자주 쓰는 것은 늘 보이고 한 번에 누를 수 있게, 드문 것은 관리에 모읍니다.

## 2. 지도: 네 자리

| 자리 | 하는 일 | 안에 있는 것 |
|---|---|---|
| **플레이** (기본) | 게임하면서 보는 곳 | 맵 · 보조 · 치트 · 읽기(빠르게 보기) |
| **읽기** | 게임을 켜든 끄든 내 플레이를 다시 읽는 곳 | `이야기 \| 모든 기록` |
| **찾아보기** | 게임 없이 이벤트·대사를 찾는 곳 | `이벤트 \| 못 본 것` |
| **관리** | 가끔 하는 설정·관리 | 연결·실행 · 세이브 백업 · 휴대폰으로 보기 · 게임 맞춤 설정 · 진단 · 화면 · 게임 바꾸기 |

검색(Ctrl+K)은 어디서나 열립니다.

### 기능 하나에 집 하나

- 기능은 **한 자리에서만 삽니다.** 다른 곳에는 그 자리로 데려가는 링크나, 같은 컴포넌트를 쓰는 빠른 실행만 둡니다(예: 보조의 "지금 백업"은 관리 › 세이브 백업과 같은 동작).
- 같은 일을 하는 버튼을 화면마다 새로 만들지 않습니다. 하나의 훅/컴포넌트를 만들어 모든 자리에서 씁니다(예: 설치·업데이트·실행은 모두 `ConnectionAction` 하나).
- **왜**: 리디자인 전 백업 버튼이 7곳, 치트·보조가 4곳에 있어서 사용자가 어느 것이 진짜인지 헷갈렸고, 화면마다 동작이 조금씩 달랐습니다.

### 새 기능은 어디에?

| 이런 기능이면 | 여기에 |
|---|---|
| 게임 중에 자주 누르는 조작 | 플레이 › 보조 (상황별 카드 안). 고정하면 빠른 막대에 |
| 게임 상태를 바꾸는 값 조작 | 플레이 › 치트 |
| 지금 맵에서 할 것·갈 곳 | 플레이 › 맵 (구역 칩·해 볼 것·다음 스토리) |
| 지난 플레이를 보여 주는 것 | 읽기 (게임이 꺼져 있어도 동작해야 함) |
| 게임 데이터 자체를 살펴보는 것 | 찾아보기 |
| 한 번 정하고 잘 안 바꾸는 설정 | 관리의 알맞은 섹션 (없으면 섹션을 새로 만들기 전에 기존 섹션에 넣을 수 있는지 먼저 봄) |
| 기기마다 다른 개인 설정(테마·소리) | 그 설정을 쓰는 화면의 보기 설정 + 필요하면 관리 › 화면, 저장은 기기별(localStorage) |

**맨 위 자리를 늘리지 않습니다.** 다섯째 자리가 필요해 보이면 기존 네 곳 안에 들어갈 수 없는 이유를 먼저 적어 주세요.

## 3. 화면 골격

- **머리줄은 한 줄**: `[게임 이름 ▾][연결 상태] · 맵 이름 …… [플레이·읽기·찾아보기·관리] [검색]`. 두 줄로 쌓이거나 버튼이 늘어나면 안 됩니다. 새 버튼을 머리줄에 넣지 않습니다.
- **빠른 막대**(플레이, 연결됐을 때만): 사용자가 핀으로 고정한 보조 조작. 한 줄, 넘치면 가로 스크롤. 항목 사이는 구분선, 값을 고르는 묶음에는 짧은 이름표.
- **전투 막대**: 전투 중에는 빠른 막대 전체가 빨간 전투 막대로 바뀝니다(이기기·도망·지기·적 체력·내 체력·배속). 고정하지 않아도 나옵니다. **왜**: 전투는 짧고 급해서, 사용자가 찾게 하지 말고 화면이 먼저 바뀌어야 합니다.
- **PC 플레이(900px 이상)**: 왼쪽 맵 칸(위 구역 칩, 가운데 맵 그림, 아래 `다음 스토리 | 해 볼 것` 탭) + 오른쪽 도구 칸(`보조 | 치트 | 읽기`). 크기는 기억합니다.
- **900px 미만·휴대폰**: 아래 탭 막대 `맵 · 보조 · 치트 · 읽기 · 더보기`. PC 도구 칸과 순서가 같습니다.
- 정보가 많은 것을 좁은 칸에 욱여넣지 않습니다. 함께 볼 필요가 없으면 탭으로 나눠 각자 공간을 줍니다. **왜**: 다음 스토리 카드를 해 볼 것 목록과 한 칸에 넣었더니 잘려서 읽을 수 없었습니다.

## 4. PC와 휴대폰

- 이름·순서·아이콘이 같아야 합니다. 넓이에 따라 펼쳐 보이는 정도만 다릅니다.
- 같은 내용은 같은 컴포넌트로 그리고, 껍데기만 바꿉니다: PC는 Popover/Sheet, 휴대폰은 Drawer.
- 휴대폰 보기(원격)에서 못 하는 일(설치·실행·백업·휴대폰 연결 등)은 버튼을 숨기거나 흐리게 두고 "PC에서 해 주세요" 한 줄로 알립니다. 사라져서 못 찾게 만들지 않습니다.
- 터치 기기에서는 누르는 컨트롤이 최소 40px입니다(`index.css`의 `pointer: coarse` 규칙).

## 5. 상태 안내

### 한 화면에 안내는 하나

- 한 화면에는 **지금 필요한 것 하나만** 말합니다. 같은 안내를 칸마다·탭마다 반복하지 않습니다.
- 안내는 **제목(지금 할 일) + 한 문장 + 버튼 하나**입니다. 번호 목록·긴 문단을 쓰지 않습니다. 단계가 있으면 작은 진행 표시(✓ 끝난 단계, 강조된 지금 단계)만 둡니다.
- 일반적인 말("게임과 연결되지 않았어요") 대신 진짜 이유를 제목으로 씁니다("기록 플러그인이 필요해요", "업데이트해 주세요", "게임을 실행해 주세요").
- **왜**: 플레이 화면에 "게임과 연결되지 않았어요"와 "기록 플러그인 설치해 주세요"가 같이 보여 헷갈렸고, 진짜 해야 할 일의 버튼은 작게 숨어 있었습니다.

### 해야 할 일은 그 자리에서 바로

- 사용자에게 무언가를 하라고 하면, **그 자리에 그 일을 하는 버튼**을 둡니다. "관리에서 자세히" 같은 링크로 떠넘기지 않습니다.
- 연결 상태 단추를 누르면 플러그인 상태·버전, 설치/업데이트/게임 실행, 게임 위치 바꾸기를 그 자리에서 다룹니다.
- 경고 띠(플러그인 설치·업데이트)는 이미 같은 버튼이 보이는 화면(플레이 안내, 관리 › 연결·실행)에서는 띄우지 않습니다.

### 순간 메시지는 토스트로

- "실행했어요", "복원했어요", "복사했어요", "보냄…", 실패 메시지처럼 **한 번 알리고 끝나는 결과는 반드시 토스트**(shadcn Sonner `toast.success`/`toast.error`)로 보냅니다.
- 버튼 옆에 글을 끼워 넣어 레이아웃을 밀어내는 방식은 쓰지 않습니다.
- 화면에 남겨 두는 것은 **계속 유지되는 상태**뿐입니다: 계속 유효한 경고 Alert, 대화상자 안의 입력 오류, 목록을 못 읽은 오류.
- **왜**: "실행했어요"가 레이아웃 안에 나타났다 사라지며 화면을 해쳤습니다.

### 숫자와 알림 배지는 따라가면 찾을 수 있게

- 배지 숫자는 **눌러 들어가면 같은 숫자가 보이는 자리**까지 이어져야 합니다. 관리 배지 → 해당 섹션 배지 → 섹션 맨 위의 같은 색 "할 일 N개".
- 배지가 있으면 그 링크는 문제가 있는 섹션으로 바로 데려갑니다.
- 같은 뜻의 숫자는 어디서나 같은 값입니다(예: "해 볼 것 N"은 항상 `checklist.remaining`).
- **왜**: 관리에 "확인 필요" 배지가 떴는데 들어가서 어디가 문제인지 몰라 헤맸습니다.

### 사용자의 언어로 결론부터

- 결과 화면(진단 등)은 기술 분류(그림/화면/기타)가 아니라 **사용자가 할 일 순서**로 놓습니다: 결론 한 문장 → 할 일 → 뷰어가 알아서 처리한 것(접음) → 문제 없음(접음) → 문제가 계속되면.
- 상태 이름표("자동 처리", "괜찮아요")만 붙이지 말고, 사용자가 무엇을 하면 되는지(또는 아무것도 안 해도 되는지)를 문장으로 씁니다.

## 6. 읽기는 게임이 꺼져도 동작

- 플레이 기록(`rpg-viewer/log.jsonl`)만 있으면 읽기는 연결 여부와 상관없이 보여야 합니다. "지금" 카드처럼 연결이 필요한 조각만 숨깁니다.
- 연결 상태로 화면 전체를 막는 조건(`connection !== "connected"`이면 안내로 바꾸기)은 **정말 게임이 켜져 있어야만 의미 있는 화면**(맵·보조·치트)에만 씁니다. 연결은 5초 동안 소식이 없으면 끊긴 것으로 바뀌므로, 이런 조건은 화면을 자주 깜빡이게 하고 그 아래 내용(그림·음성)을 날려 버립니다.
- **왜**: 읽기를 플레이 안의 탭으로만 두고 연결로 막았더니, 게임을 끄면 지난 플레이를 볼 수 없었고 캐릭터 그림도 사라졌습니다.

## 7. 색

바탕·글·테두리는 shadcn neutral 그대로입니다. 색은 **뜻이 있을 때만** 씁니다. 팔레트 클래스(`bg-red-500` 등)는 쓰지 않고 토큰만 씁니다.

| 토큰 | 뜻 | 쓰는 곳 |
|---|---|---|
| `success` | 잘 되고 있음 | 게임 켜짐 점, 진단 "할 일 없음" |
| `warning` | 손이 필요함 | 플러그인 설치·업데이트, 연결 확인 중, 확인할 것 배지 |
| `info` | 새로운 것 | 새 대사 N, 확실하지 않은 것 |
| `destructive` | 위험·오류·**전투** | 오류, 삭제·복원 확인, 전투 막대 |
| `primary` | 켜짐·선택됨·주 동작 | 켜진 Toggle/ToggleGroup(채움), 기본 버튼 |
| `section-*` | 맵 구역 | 맵 점, 구역 칩, 해 볼 것 목록 제목 점. **이 밖에서 쓰지 않음** |

- 켜진 토글은 primary로 채워서, 켜졌는지 한눈에 보이게 합니다(연회색 금지).
- 예외: 고정 핀은 채운 사각형 대신 채운 핀 아이콘으로 켜짐을 보입니다(작은 아이콘이 화면을 압도하지 않게).
- 쓸 수 없는 버튼은 흐리게 두고, 이유가 있으면 Tooltip으로 알려 줍니다.
- 밝게·어둡게 둘 다에서 읽히는지 확인합니다. 테마는 기본 "시스템"입니다.

## 8. 컴포넌트

- **shadcn/ui 컴포넌트와 공식 예시 모양만** 씁니다. 없으면 공식 컴포넌트를 추가하거나 shadcn 조각을 조합합니다. 새 디자인 언어를 만들지 않습니다.
- 고르는 기준:
  - 잠깐 보고 닫는 작은 패널(연결 상태, 보기 설정): PC Popover / 휴대폰 Drawer
  - 길게 읽는 보조 내용(어떻게 하나요, 상호참조): Sheet
  - 되돌리기 어려운 확인(삭제·복원·제거·지기): AlertDialog
  - 순간 결과: 토스트(Sonner)
  - 비었을 때: Empty (제목 + 한 문장 + 버튼 하나)
  - 접어 둘 부차 정보: Collapsible
- 누를 수 있는 것은 누를 수 있게 보여야 합니다. 참조 칩은 칩 전체가 눌리고 오른쪽에 ↗가 있습니다. 누를 수 없는 것에는 ↗를 쓰지 않습니다.

## 9. 말

- 화면에 같은 개념을 부르는 이름은 `src/ui/terms.ts` 한 곳에 두고 거기서 가져다 씁니다.
- 말투는 "-요". core에서 온 "-습니다" 글은 `casual()`로 바꿔 보여 줍니다.
- 하나로 쓸 말:

| 쓸 말 | 쓰지 않을 말 |
|---|---|
| 해 볼 것 N | 남은 것, 할 것 N개 남음 |
| 보조 | 게임 보조 |
| 찾아보기 | 탐색기, 탐색 목록 |
| 기록 플러그인 | 플러그인(단독), 브리지 |
| 세이브 백업 | 백업(제목으로 쓸 때) |
| 게임 맞춤 설정 | 게임 설정 |
| 빠른 막대에 고정 | 즐겨찾기, 위쪽 막대 |
| 게임 켜짐 / 게임 꺼짐 / 연결 확인 중 | 연결됨, ● 연결됨 |

- 자리 이름이 들어간 말은 그 자리로 데려갈 때만 씁니다. "찾아보기"로 가지 않는 링크에 "찾아보기"라고 쓰지 않습니다.
- 위치를 가리키는 말은 사용자가 화면에서 찾을 수 있어야 합니다("위쪽 막대"가 아니라 이름이 있는 "빠른 막대", 그리고 Tooltip에 "플레이 화면 맨 위").
- 어려운 말(회차·갈래, 기록에 없는 세이브, 이렇게 본 이유)은 Tooltip 한 줄로 풀어 줍니다.

## 10. 새 화면·기능을 넣을 때 확인 목록

- [ ] 2절 표로 자리를 정했고, 같은 기능이 다른 곳에 이미 있지 않다.
- [ ] 머리줄이 한 줄 그대로다. 새 버튼을 머리줄에 넣지 않았다.
- [ ] PC와 휴대폰에서 이름·순서가 같고, 휴대폰 보기에서 못 하는 일은 "PC에서 해 주세요"로 알린다.
- [ ] 한 화면에 안내가 하나뿐이고, 할 일을 말하면 그 자리에 버튼이 있다.
- [ ] 순간 결과는 토스트로만 보낸다. 레이아웃을 밀어내는 글이 없다.
